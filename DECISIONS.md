# Реестр решений

Дата: 2026-11-21. Здесь различаются требования владельца, организационные решения и **непринятые** технические рекомендации.

## Подтверждено владельцем
- D001: без обязательных внешних AI API/сервисов; локальная алгоритмическая генерация.
- D002: Visual First, доступность начинающим при профессиональном контроле, расширяемость; 2D и Generative Art не второстепенны.
- D003: main не менять напрямую, merge только по разрешению, исследования двух авторов разделять.
- D004: стек и формат сохранения пока не приняты. Не считать примеры C++/Qt/Vulkan/Python/JSON решениями.
- D005: независимая оценка → интеграция → критическая рецензия → согласование владельца до массовой реализации.

## Организация текущего пакета
- D006: использовать существующие имена семи документов; собственные исследования поместить в docs/research/gpt/. Причина: раздел 25 мастер-промпта важнее ранней примерной структуры.
- D007: предполагаемая база ветки — project-foundation, поскольку там создана структура пользователя. Это не merge в main. При переносе повторно проверить базу.
- D008 (история): из-за первоначального 403 подготовлен локальный overlay и архив. После восстановления прав ветка создана от проверенной project-foundation; пакет переносится без записи в main. Это восстановление разрешённого рабочего процесса, не обход контроля доступа.

## Только предложения
- P001: тонкий typed demand-driven executor + специализированные домены; не строить универсальный язык/компилятор заранее.
- P002: A (Rust + native egui/eframe + wgpu) — первая гипотеза для проверки баланса, не победитель по измерениям.
- P003: C (Tauri + web UI + Rust CPU) — конкурент при сильных web-компетенциях, но требует отдельного доказательства preview/GPU межпроцессного пути.
- P004: B (C++ + Qt + специализированный Vulkan/Metal renderer) — кандидат при доказанном требовании low-level GPU контроля, не «автоматически самый быстрый».
- P005: internal seed/versioned algorithms и cache invalidation нужны рано; полный plugin marketplace, JIT, distributed compute и все виды физики — нет.

Каждое принятое позднее решение должно включать статус, владельца согласования, контекст, альтернативы, доказательства, последствия и условие пересмотра. Оценка источников не заменяет benchmark и согласование.
