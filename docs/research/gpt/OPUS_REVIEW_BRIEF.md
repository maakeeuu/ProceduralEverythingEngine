## Цель
Не подтвердить выбор автора, а независимо решить, какая архитектура реалистична для заданного продукта и команды. Найти сильные контрпримеры, упущенные риски и более дешёвые способы доказать/опровергнуть подходы. Не начинать массовую реализацию и не выбирать окончательный стек.

3. Проверить источники независимо, особенно mutable latest/release status/licensing. Не ссылаться на формулировки первой оценки как на доказательство.

## Вопросы для реальной критики
- Покрывают ли предложенные типы field/image/mask/height/mesh/material/scene/layers реальные междоменные операции без универсального god-object?
- Где контракты несовместимы с tiled/ROI evaluation, topology changes, deferred GPU compute или stateful simulation?
- Какие части resource broker/cache key избыточны для первого среза, а какие критически отсутствуют?
- Можно ли сохранить один GPU-resident pipeline с egui/wgpu? Какова реальная цена webview/native interop в C и Qt/custom renderer в B?
- Какие лицензии/версии/поддержка делают вариант непригодным? Нужно ли пересмотреть macOS Vulkan path с учётом статуса upstream?
- Не выдаётся ли Rust/Wasm/Tauri/process separation за sandbox? Какие host-call/compilation/driver атаки остаются?
- Реально ли UX Visual First на предложенном UI toolkit, включая Cyrillic/IME/keyboard/HiDPI/accessibility?
- Достаточно ли срез доказывает platform, а не набор красивых картинок? Какой самый дешёвый эксперимент способен опровергнуть каждую гипотезу?
- Правильно ли отложены домены, project format и SDK, не создавая будущих необратимых ограничений?

## Формат результата
Создать `docs/research/opus/INDEPENDENT_ASSESSMENT.md` и при необходимости отдельные материалы в этой директории, в своей ветке. Не переписывать GPT docs и не редактировать core одновременно с другим исполнителем. Каждый вывод: факт/оценка/гипотеза; источник+дата; severity; предложение; эксперимент; условие изменения вывода.

Нужны: собственные A/B/C либо аргументированная другая классификация, минимум сильнейших возражений без искусственной квоты, missing requirements, согласия/противоречия и ранжированный план проверок. Не объявлять тесты пройденными без запуска.
