## T1. Не единый универсальный граф данных, а общий исполнительный субстрат + доменные вычислители [О]

- **Общий субстрат** включает:
  - планировщик задач: CPU work-stealing и GPU-очередь;
  - кэш с бюджетом памяти и менеджер ресурсов: RAM/VRAM, резидентность данных;
  - отмену по поколению запроса, диагностику и ошибки, детерминированные seed'ы;
  - реестр типов и конвертеров;
  - реестр нод через тот же API, что и для плагинов.
- **Доменные вычислители**: Field (ленивые функции координат), Image/Raster, Geometry (атрибутная), Vector2D, Material, Scene, Layers/Composition. У каждого — своя семантика и свои оптимизации.
- Документ проекта — набор сущностей разных видов: нодовые графы, стек слоёв, сцена. Их связывает общая модель зависимостей, но не общий тип данных.

## T2. Междоменный «клей» — Field<T>, а не растровое изображение [О]

- Опора: в Blender поле — это функция, вычисляемая многократно на разных входных данных [Ф: https://docs.blender.org/manual/en/latest/modeling/geometry_nodes/fields.html].
- Цепочка Voronoi → Distortion → Symmetry → Color Mapping естественно является Field. Дальше три явных шага:
  - растеризация: `Rasterize: Field → Image` с явным разрешением;
  - выборка на геометрии: `Sample: Field → атрибут`;
  - использование в материале: компиляция в шейдер.
- Не всё является Field. Reaction-diffusion, эрозия, клеточные автоматы, L-системы и space colonization — итеративные процессы с состоянием. Они порождают **материализованные** данные: сетки, изображения, геометрию.
- Отсюда два класса операций:
  - точечно-вычислимые: их можно сливать в одно GPU-ядро;
  - материализующие: буферы и симуляции.

## T3. Модель выполнения: pull-вычисление по запросу + мемоизация + early cutoff [О]

- Ключ кэша: версия определения ноды, хэш параметров, хэши входов и контекст вычисления (разрешение/LOD, время, seed).
- Если хэш выхода не изменился, инвалидация дальше не распространяется (early cutoff).
- Теоретическая рамка — Mokhov, Mitchell, Peyton Jones, «Build Systems à la Carte», ICFP 2018 [Ф: https://simon.peytonjones.org/build-systems-a-la-carte].
- Близкий практический аналог — Salsa [Ф: https://github.com/salsa-rs/salsa].

## T4. Preview-first [О]

- Прогрессивное вычисление: сначала низкое разрешение, затем уточнение.
- Отмена по поколению запроса; приоритет — у видимых viewer'ов и миниатюр.

## T5. CPU/GPU [О]

- На GPU: полевые и растровые операции. На CPU: топологически сложная геометрия — булевы операции, топология subdivision, remeshing.
- Без ping-pong между CPU и GPU:
  - менеджер ресурсов учитывает резидентность данных;
  - последовательные GPU-операции группируются в одну отправку;
  - цепочки Field-операций сливаются в одно ядро (codegen) — ожидаемо главный источник производительности.

## T6. Модель данных [О]

- Неизменяемые значения со структурным разделением и copy-on-write. Аналог — Blender implicit sharing [Ф: https://developer.blender.org/docs/features/core/implicit_sharing].
- **Геометрия** — атрибутная. Домены point/vertex/primitive/detail — как в Houdini [Ф: https://www.sidefx.com/docs/houdini/model/attributes.html].
- **Изображения** типизированы: число каналов, формат u8/u16/f16/f32, цветовое пространство.
- **Вектор** — пути Bézier + стиль; растеризация только явная.

## T7. Наивное кэширование всего невозможно [О, арифметика]

- RGBA f32 8192² = 8192·8192·16 Б = 1 ГиБ на один выход ноды.
- Поэтому нужны:
  - бюджеты RAM/VRAM;
  - f16 для превью;
  - тайлы;
  - вытеснение с учётом стоимости пересчёта;
  - явная «заморозка» (bake/lock) пользователем.

## T8. Нодовая система [О]

- Поток данных — DAG. Циклы допускаются только в явных конструкциях: repeat/loop-зона, solver с явным состоянием между кадрами.
- Порты типизированы, конвертеры — явные ноды. Короткий список безопасных неявных конверсий, например `Float → Field<Float>`.
- Подграф = нода. Генератор = подграф с опубликованным интерфейсом, метаданными и пресетами.
- Шаблон и генератор — один механизм ассетов с двумя режимами вставки: ссылка или копия.
- Стабильные ID нод и версия определения каждой ноды — с первого дня. Иначе миграции невозможны.

## T9. Три уровня расширяемости [О]

1. Встроенные ноды регистрируются через тот же API, что и плагины (dogfooding).
2. Пользовательские поэлементные вычисления (пиксель, точка) пишутся на собственном типизированном языке выражений/ядер. Он компилируется в тот же IR, что и Field-ноды: ноды и текст — два представления одного IR.
3. Нативные расширения:
   - для сторонних по умолчанию — WASM-компоненты в песочнице;
   - нативные динамические библиотеки — только с «полным доверием» или вне процесса.

## T10. Скрипты [О + Ф]

- Python — де-факто стандарт автоматизации в DCC. Надёжно изолировать его внутри процесса нельзя [О].
- Free-threaded CPython официально поддерживается с 3.14, но не по умолчанию [Ф: PEP 779, Status Final — https://peps.python.org/pep-0779].
- Для стороннего кода — Luau: у него документирована модель песочницы и прерываний [Ф: https://luau.org/sandbox]. Альтернатива — WASM.
- Python — опционально, как «доверенная автоматизация» с явным предупреждением.

## T11. Безопасность плагинов [О + Ф]

- Подпись подтверждает происхождение, а не безопасность.
- Модель угроз:
  - вредоносный пакет с GitHub;
  - чтение и вынос файлов;
  - сеть;
  - DoS: бесконечный цикл, память, зависание GPU.
- Механизмы защиты:
  - Wasmtime: fuel, epoch-прерывания, ResourceLimiter [Ф: https://docs.wasmtime.dev/examples-interrupting-wasm.html, https://docs.wasmtime.dev/api/wasmtime/struct.Store.html];
  - capability-модель WASI;
  - доступ к GPU — только через шейдеры, которые валидирует хост (naga/wgpu), а не через сырое устройство;
  - watchdog и восстановление после device lost.
- Блог wasi-gfx от 2026-06-07: `wasi:webgpu` остаётся WASI-спецификацией, остальной wasi-gfx выносится в отдельное пространство имён [Ф: https://wasi-gfx.dev/blog/posts/future-of-wasi-gfx]. Вывод: прямой GPU из WASM пока не основа архитектуры [О].

## T12. Стек — предварительная позиция, не решение [О]

- **A (баланс):**
  - Rust для ядра и доменов;
  - wgpu: WGSL/naga, Vulkan/Metal/DX12/GLES [Ф: https://wgpu.rs/], текущая версия v30.0.2 [Ф: https://crates.io/crates/wgpu];
  - UI-оболочка на Rust с кастомными GPU-канвасами; egui или Slint — выбор по эксперименту;
  - fallback — Qt 6 через C ABI.
- **B (производительность):**
  - C++20/23 + Vulkan 1.4 [Ф: https://vulkan.org/news/auto-23155-a676f167a3982c6a4f6d36a46284cad8] + Slang [Ф: https://shader-slang.org/news/2024/11/21/khronos-hosts-open-source-slang-shading-language-and-compiler] + Qt 6;
  - oneTBB или Taskflow;
  - VFX-библиотеки: OpenSubdiv, OpenVDB/NanoVDB, OIIO, OCIO, Embree, MaterialX, OpenUSD;
  - Python как доверенный язык; внепроцессная песочница для недоверенного нативного кода.
- **C (малая команда / AI-assisted):** подмножество A без перехода на другой стек.
  - Rust + wgpu + egui;
  - без C++ FFI в v1;
  - Field DSL вместо внешнего скриптового языка;
  - плагины только WASM.
- Во всех вариантах обязательно **headless-ядро** (библиотека + CLI). UI — сменяемый слой.
- Предварительная траектория: C → A. Вариант B — только если эксперимент докажет узкое место, а не по умолчанию.

## T13. Минимальный вертикальный срез [О]

- Основная цепочка: Field-паттерн → Image → Heightmap → displacement меша → PBR-материал → viewport → экспорт (PNG16/EXR + glTF/GLB).
- Одна итеративная нода: Gray-Scott reaction-diffusion на GPU.
- Инфраструктура среза:
  - живые миниатюры и отмена;
  - кэш с бюджетом;
  - детерминированные seed'ы;
  - undo/redo;
  - дизайн-токены;
  - сохранение v0, явно помеченное как нестабильное.
