## Непроверенные гипотезы (рабочие; будут разобраны в документах)
- H1. Междоменный «клей» — ленивое поле Field<T>. Плюс явные материализующие операции: Rasterize, Sample, Bake. Покрывает сквозной сценарий без универсального god-object (снимок, T2).
- H2. Цепочки точечных Field-операций выгоднее компилировать в один GPU-проход, чем исполнять по ноде с промежуточными текстурами. Влияет на VRAM и стоимость миниатюр. Не измерено.
- H3. Минимальный типизированный IR для полей — не «универсальный компилятор». Это CPU-интерпретатор пакетами плюс генерация WGSL. Его стоимость приемлема для малой команды. Здесь частичное противоречие с P001 GPT.
- H4. Первая сетка — полигональная SoA (face offsets/corners/edges), а не indexed triangles. Это дешевле будущей миграции.
- H5. Вертикальный срез GPT не нагружает самые рискованные контракты: нелокальные операции, итеративное состояние, смену топологии.
- H6. egui пригоден для продуктового UI при строгом отделении модели представления. Не проверено.
- H7. Для GPU-ориентированного продукта вариант C GPT (Tauri/web) добавляет структурную границу GPU/IPC. Вариант «C = подмножество A» дешевле по совокупной сложности. Не проверено.
